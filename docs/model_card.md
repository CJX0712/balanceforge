# Model Card — BalanceForge MOSAIC

Author: 晨星 (CJX0712) · Version 0.1.0

---

## Intended use

**MOSAIC** is a rebalancing layer for supervised classification on imbalanced
data. It sits between a dataset and any probabilistic classifier, and is
intended for:

* binary (and, with caveats, multi-class) classification where the minority
  class matters at least as much as the majority;
* tabular, low-to-moderate dimensional data (4–10 features in the benchmark);
* settings where the class prior at inference is **known** and is the same
  prior observed in training.

**Out of scope**:

* regression with skewed residuals (use quantile regression instead);
* streaming / online imbalance (see the `prequential` literature — BalanceForge
  is batch-only);
* multi-label problems;
* data with a genuine label-noise problem. MOSAIC's gate assumes class overlap
  is geometric, not the result of corrupted labels; it will happily
  over-synthesise a noise cloud. Use the `minority_noise_fraction` statistic in
  the profile to detect that case.

## Data

All benchmark data is **synthetic**, generated by
`balanceforge/data/datasets.py`. No real-world dataset, no personal data, no
network access at run time.

| dataset | geometry | n (maj/min) | IR | difficulty dial |
|---|---|---|---|---|
| `separable` | minority ring inside majority shell | 1200 / 120 | 10 | `imratio`, `d` |
| `overlap` | minority straddles the majority mode | 2000 / 250 | 8 | `sep`, `imratio`, `d` |
| `multimodal` | 3 detached minority islands | 1200 / 80 | 15 | `k_modes`, `imratio` |
| `sparse` | few minority, large majority | 3000 / 100 | 30 | `imratio`, `d` |
| `manifold` | minority on a 1-D curve inside the bulk | 3000 / 150 | 20 | `imratio`, `d` |

Every generator is a pure function of `(seed, knobs)`, so any reported number
can be regenerated exactly.

**Difficulty dials were measured, not assumed.** Each shipped setting was
chosen by sweeping for a *discriminative* operating point — one where naive and
strong baselines genuinely separate. Two settings were rejected outright
because they made the benchmark meaningless (see §Limitations).

## Metrics

**Primary**: `gmean` — geometric mean of per-class recall (Kubat & Holte).
Maximised, in `[0, 1]`.

* `gmean = 0` if any class has zero recall;
* `gmean = 1` for a perfect classifier;
* `gmean <= balanced_accuracy` always (a geometric mean never exceeds the
  arithmetic mean of the same recalls).

**Why G-mean and not accuracy**: accuracy on a 1:30 dataset is ≈ 0.97 for the
constant-majority predictor. It carries essentially no signal.

**Why not AUC**: AUC is provably invariant to the class prior, so it cannot
measure whether a method fixed the imbalance — only whether the *ranking* is
good. G-mean is prior-sensitive in the right way.

**Secondary**: `macro_f1`, `balanced_accuracy`, `mcc`, `minority_recall`,
`minority_precision`, `au_prc` (binary only), and the full per-class recall
vector. G-mean alone is **not** a sufficient summary: heavy under-sampling can
post a high G-mean with a poor MCC, because discarding majority evidence
inflates minority recall at the cost of precision. Both are reported for
exactly that reason.

**Reporting rule**: all comparisons use ≥ 3 seeds and report mean ± std. A win
requires (a) mean difference above the declared effect size and (b) mean
difference above `½(σ_method + σ_base)`. Single-run numbers are not accepted.

## Method summary

Three stages, each independently switchable (see `docs/architecture.md`):

1. **Geometry routing** — an MST plateau-width cluster detector plus overlap,
   entropy and IR statistics classify the dataset as `separable` / `overlap` /
   `multimodal` / `sparse`, and pick a matching remedy. Includes a **negative
   route**: on `separable` data at ceiling, resampling is forbidden outright.
2. **Contamination-gated SMOTE** — each candidate k-NN synthesis segment is
   scored by its proximity excess to the majority set and admitted with
   probability `exp(−c²/2σ_c²)`. Degenerates to plain SMOTE when nothing is
   contaminated.
3. **Prior-matched calibration** — a zero-hyper-parameter closed-form prior
   correction `s_c = log q_c − log π_c`, optionally followed by a validation-
   only coordinate ascent over a fixed offset grid, with a Wilson floor on the
   objective and a sample-size admissibility gate.

## Ablations

Three component switches, each measured on the full suite:

| variant | what is removed | expected effect |
|---|---|---|
| `no_gate` | `sigma_c → ∞`, every segment admitted | reintroduces cross-class synthesis; degrades `overlap` and `manifold` |
| `no_route` | always use gated SMOTE | loses per-mode expansion on `multimodal` and condensation on `sparse` |
| `no_prior` | `prior_correction = False` | largest single drop: the prior correction alone accounts for most of the gain over `class_weight` |
| `no_calib` | learned offsets disabled | minor relative to `no_prior`; the closed-form term does most of the work |

Ablation numbers are generated by `examples/run_demo.py --ablation` and stored
in `benchmark.json` under `ablation`. The component-level verdict is that
Stage 3 (prior correction) carries the majority of the improvement and Stage 2
(the gate) contributes most specifically on the overlapping regimes.

## Limitations

* **Binary only in practice.** The estimator factory and data contract support
  `n` classes, but the contamination gate's `|M| / n_min` normalisation and the
  Wilson floor are written for the binary case.
* **The benchmark's difficulty knobs were tuned; the results are not a claim
  about real-world data.** Two settings were rejected as uninformative:
  `sparse` at `imratio=400` (3 minority samples in the test split → G-mean
  became a coin flip) and `overlap` at `imratio=20` (18 test minority samples →
  cross-method std 0.28, which is sampling noise). The shipped settings fix
  both, but the underlying fragility — *imbalance benchmarks are extremely
  sensitive to how many minority samples reach the holdout* — is a property of
  the field, not something this project fixes.
* **`multimodal` per-mode expansion is implemented but not yet clearly
  validated.** With `k=3` islands a global budget already covers every mode, so
  the measured gain over plain gated-SMOTE sits inside seed noise.
* **The cluster detector is `O(n_min²)`.** Acceptable at the shipped sizes;
  it would need a k-NN graph approximation beyond `imratio ≈ 1000`.
* **Overfitting to synthetic geometry.** MOSAIC is verified only on the five
  geometries in `datasets.py`. Real data has structure none of them capture.
* **Calibration is only as good as the validation split.** The sample-size gate
  (`MIN_CLASS_SAMPLES_FOR_CALIBRATION = 15`) is a blunt instrument: a class
  with 16 samples passes, but the Wilson floor is what actually protects the
  optimisation there, not the gate.

## Intended misuse

* Applying prior correction when the **inference prior differs from the training
  prior**. BalanceForge assumes they match; `detect_already_balanced()` guards
  against double-correction by internally-balanced models, but it cannot detect
  a genuine prior shift between train and deployment.
* Reporting G-mean without also reporting MCC on heavily under-sampled
  datasets. See §Metrics.
* Treating a non-significant delta as a win. The gate requires `½σ` separation;
  the honest result when it fails is "no difference detected".

---

## Ethical considerations

Class-imbalance handling is usually deployed in fraud detection, medical
diagnosis and content moderation — domains where false negatives carry real
harm. Two specific cautions:

* **Raising minority recall is not free.** Every G-mean gain in this repo was
  paid for in majority-class recall. Report the confusion matrix, not just the
  aggregate.
* **Balanced error rates are not fair error rates.** Equalising per-class
  recall can be the wrong objective when the two classes have different
  consequences. BalanceForge optimises a statistical criterion, not an ethical
  one; choosing the criterion is the practitioner's job.

## Reproducing every number in this card

```bash
git clone https://github.com/CJX0712/balanceforge
cd balanceforge
python -m pip install -e ".[test]"
python examples/run_demo.py
```

Two runs with the same seed produce bit-identical metric values. All figures
in `README.md` and this card come from `benchmark.json` in the repository root.
